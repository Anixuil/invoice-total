# Repository Guidelines

## Project Structure & Module Organization

This repository provides a local FastAPI workspace for invoice verification, Jira workbook processing, and weekly-report generation.

- `invoice_total.py`: core extraction engine, reconciliation logic, confidence scoring, and CLI entry point.
- `server.py`: FastAPI application exposing the upload API and serving the frontend.
- `static/index.html`: self-contained browser UI (HTML, CSS, and JavaScript).
- `jira_processor.py` and `static/jira.html`: Jira workbook rules, preview tables, and Excel export.
- `weekly_report_processor.py`, `static/weekly-report.html`, and `templates/`: ZIP 内 PPTX 审核合并、周例会 DOCX 填充和审核报告生成。
- `static/page-transition.js` and `static/page-transition.css`: shared SPA navigation, route caching, transitions, and scrollbar styling.
- `make_sample_invoice.py`: deterministic sample-PDF generator for manual regression checks.
- `sample_invoice.pdf`: checked-in fixture generated by the sample script.
- `requirements.txt`: Python runtime dependencies.

Keep business rules in the corresponding processor (`invoice_total.py`, `jira_processor.py`, or `weekly_report_processor.py`); avoid duplicating them in API or UI code. Uploaded office files are processed in temporary job directories and are not committed.

## Build, Test, and Development Commands

Create and activate a virtual environment, then install dependencies:

```bash
python -m venv .venv
python -m pip install -r requirements.txt
```

Common workflows:

```bash
python invoice_total.py sample_invoice.pdf
python invoice_total.py ./invoice-directory --json
python make_sample_invoice.py sample_invoice.pdf
uvicorn server:app --reload --port 8000
```

The first two commands exercise CLI extraction; the generator recreates the two-page fixture (expected total: `2416.00`). Uvicorn starts the three-module UI at `http://localhost:8000`; the Jira and weekly-report routes are `/jira` and `/weekly-report`.

## Coding Style & Naming Conventions

Use Python 3 type-friendly code with four-space indentation and UTF-8 source files. Follow PEP 8: `snake_case` for functions and variables, `PascalCase` for classes, and `UPPER_SNAKE_CASE` for constants. Keep parsing helpers small, preserve two-decimal monetary rounding, and document non-obvious invoice heuristics. Frontend code should retain the existing two-space CSS/JavaScript indentation and dependency-free structure. No formatter or linter is currently configured.

## Testing Guidelines

There is no automated test suite yet. For extraction changes, add focused tests under `tests/` using names such as `test_cn_upper_to_number.py`; prefer `pytest` if introducing the first suite. Cover malformed values, scanned PDFs, multiple invoices, reconciliation tolerances, and confidence boundaries. Until then, regenerate the fixture and compare CLI and JSON results against `2416.00`.

## Commit & Pull Request Guidelines

History currently follows Conventional Commit-style subjects, for example `feat: 新增PDF发票总金额提取工具`. Use concise imperative subjects such as `fix: handle blank tax cells`. Pull requests should describe the affected extraction route, include reproducible input characteristics, state expected versus actual totals, and note CLI/API impact. Add screenshots for visible UI changes, but never attach real invoices containing sensitive taxpayer data.
