# invoice-total — PDF 发票总金额提取器

多路核算 + 交叉验证 + 置信度投票，确保金额提取准确率最高。

## 用法

```bash
# 单文件
python invoice_total.py 发票.pdf

# 目录批量（自动汇总所有 PDF 的总金额）
python invoice_total.py ./发票目录

# JSON 输出（便于程序化调用）
python invoice_total.py 发票.pdf --json
```

## Web 界面

```bash
pip install -r requirements.txt
uvicorn server:app --reload --port 8000
```

浏览器访问 `http://localhost:8000`，可一次上传最多 50 个 PDF，也可以上传 ZIP 发票包。ZIP 支持多级目录，系统会递归读取其中的 PDF，并在结果顶部展示扫描到的目录清单；单个上传项上限为 20MB，ZIP 展开总量上限为 200MB。文件仅写入系统临时目录，并在本次请求处理完成后自动删除。每个 PDF 结果都会提供页面缩略图和识别合计，便于人工对照票面。

ZIP 内的结果会以 `发票包.zip / 目录 / 发票.pdf` 的形式显示。压缩包中的非 PDF 文件会被忽略；加密压缩包、路径穿越成员和超过大小限制的成员会被拒绝。上传响应会优先返回金额和置信度，票面缩略图在后台异步生成，页面通过总进度和当前 PDF 的页级子进度展示等待状态。

顶部菜单提供三个相互独立的业务模块：

- `http://localhost:8000/`：发票核验
- `http://localhost:8000/jira`：Jira 数据处理
- `http://localhost:8000/weekly-report`：周报生成与核验

## Jira 数据处理

Jira 页面接收 `.xlsx` 导出文件，并按既定表格流程自动完成：

1. 识别状态、概要、经办人、开发人员、模块和日期字段。
2. 依次按开发人员、经办人、报告人确定汇总归属；发生回退或人员不一致时进入异常清单并保留备注。
3. 将“已解决”和“已关闭”转换为“已完成”，将“处理中”转换为“进行中”。
4. 按固定人员名单排序，并把同一人员的任务合并为多行文本。
5. 在页面预览人员汇总、完整任务明细、异常清单和字段映射。
6. 下载包含上述四个工作表的处理结果 Excel。

上传文件只在临时目录中处理，任务完成后保留一小时供预览和下载，随后自动清理。

周报模式支持上传 `周报数据统计.zip` 或选择包含 Jira 导出文件的目录。系统会识别本周新增任务、本周已完成任务、本周新增缺陷、本周已修复缺陷、待处理任务和总挂起缺陷六类文件，并忽略 Excel 的 `~$` 临时锁定文件。输出当前周 23 人统计、延期/挂起明细、异常清单和处理说明；完成统计要求解决结果非空，逾期按交付日期早于报告日期且未完成判断。每日模式仍保持单文件处理。

## 周报生成与核验

周报页面接收一个包含部门全部项目周报 PPTX 的 ZIP（支持嵌套目录，ZIP 最大 500MB，展开总量最大 2GB）。`templates/weekly_report_template.pptx` 和 `templates/weekly_meeting_template.docx` 是当前内置的项目周报与部门周例会模板，仅作为版式和项目清单依据，不需要再次上传。处理器按项目标题、会议时间和会议主要内容标签定位可编辑区域，不依赖固定页码或表格行号。系统会逐页核对项目标题、汇报人、完成情况、下周计划、问题字段、页面尺寸、占位符、空白页和对象溢出，并保留 ZIP 目录供追溯。生成 PPT 后还会执行至少两轮、最多四轮内容准确度、模板样式和版面稳定度核验；自动修复可确定的问题，连续两轮达到阈值后才标记为稳定。

处理完成后会同时生成：

- `项目周报{当周周六MMDD}.pptx`：保留项目源 PPT 的页面布局和内容，按模板项目顺序合并。
- `部门周例会{当周周六MMDD}.docx`：将合并后的三类项目内容填入部门周例会模板。
- `项目周报{当周周六MMDD}-审核报告.xlsx`：包含审核结果、项目整合、周例会内容、完整文件目录和生成质量核验五个工作表。

页面提供一个 ZIP 下载按钮，一次取得上述三件文件，便于归档和人工复核。

## 四路独立核算

| 路 | 方法 | 说明 |
|----|------|------|
| ① 文本合计字段 | 正则扫描 | 定位「价税合计」行，提取（小写）金额，支持多张发票 |
| ② 表格结构合计 | pdfplumber | 表格中定位合计行/价税合计行，金额列+税额列求和 |
| ③ 中文大写金额 | 大写转数字 | 壹贰叁…圆角分整 → 数字，与阿拉伯数字互证 |
| ④ 明细行加总 | 表格明细 | 逐行金额+税额累加，还原价税合计 |

## 勾稽验证

- 金额列合计 + 税额列合计 ≈ 价税合计（容差 0.02）
- 按页面检查；文本页可用时显示通过/失败页数，图片页单独使用二维码金额
- 无法识别金额列和税额列的页面会跳过并标注“部分通过”或“不可用”，不会把图片页强行混入表格勾稽
- 通过 → 高置信度加分；未通过 → 置信度降级并提示人工核对

## 置信度规则

- **HIGH**：≥3 路一致，或 2 路一致 + 勾稽通过
- **MEDIUM**：2 路一致
- **LOW**：各路不一致 → 输出各路数值，绝不硬报一个数

## 已知限制

- 无文本层的图片页会尝试读取数电专票/普票二维码中的价税合计，并明确标注为图片页识别结果。
- 图片页没有支持的二维码时不会输出不完整总额；当前版本不包含通用 OCR。
- 低置信度代表各提取路径不一致或存在未识别图片页，不应直接作为最终财务结果。
- 建议首次遇到的新发票版式先与票面金额人工核对。
